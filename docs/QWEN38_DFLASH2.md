# Qwen 3.8: DFlash2 block-diffusion drafter

Status: landed, opt-in. `MFERENCE_DFLASH2_DIR=<dir>` (a directory holding the
z-lab/Inco `Qwen3.8-27B-DFlash2` checkpoint's `config.json` +
`model.safetensors`) swaps the speculative round's *draft source* from the
install's MTP layer to the DFlash2 drafter. The verify / accept / rollback
machinery — and therefore every emitted byte — is unchanged for any draft
quality; the drafter trades only acceptance length.

## What it is

DFlash2 (z-lab `dflash`, ICML 2026; v2 by Inco AI) replaces autoregressive
drafting with a 5-layer block-diffusion drafter: one forward pass predicts a
whole block of masked future tokens with bidirectional attention inside the
block. Conditioning is "KV injection": target hidden states after layers
{5, 19, 33, 47, 61}, concatenated and projected (`fc` + `hidden_norm`),
enter every draft layer's K/V and persist in a per-layer rotating context
cache (window 2048). V2 adds a grouped dynamic conv around attention/MLP
and a top-16 path selector. Embedding and LM head are the target's own.

## The port

- `Qwen38DFlash2Drafter` + `Metal/DFlash2/dflash2.metal`: BF16 multi-x GEMV,
  block attention over [sliding ctx | bidirectional block], dynamic conv
  (prepare/finish), top-16, tap gather. FP32 residual stream (the o/down
  projections overflow FP16 on outlier channels — the Inkling lesson).
  CPU-side greedy path selector over the codebooks.
- **INT4 at load**: projections quantize into the production multi-x INT4
  group-64 format (`DFlash2Int4Slab`, disk-cached beside the checkpoint as
  `int4-slab.cache`). The BF16 checkpoint is 3.85 GB — it thrashed the
  24 GB host against the 15 GB target and, as a file-backed GPU buffer,
  reproduced the DSV4 copy-free wiring collapse (~20x). With the slab the
  drafter is ~1.05 GB wired and a draft round is 32 ms (was 2.13 s).
  `MFERENCE_DFLASH2_BF16=1` runs unquantized (parity/reference only).
- **Taps**: the verify pass stages each tap layer's output rows for the
  drafter; prefill stages the prompt's trailing context window so the first
  rounds draft warm. Continuity breaks (plain-decode gaps, continuation
  rewinds) reset the drafter with positions realigned — quality-only.
- Draft capacity defaults to 6 when the drafter is active (block size 7 =
  anchor + 6 masks; variable block sizes are in-distribution).

## Gates

- Every kernel is CPU-reference tested (`DFlash2KernelTests`).
- The assembled core and selector match the **fp32** MLX reference across
  two rounds (`Qwen38DFlash2DrafterParityTests`, fixtures under `scratch/`,
  generated by `gen_dflash2_fixtures.py` / `gen_dflash2_f32ref.py`). The
  fp32 reference is the target because the bf16 reference disagrees with
  itself-in-fp32 by more than a correct fp16/fp32 port does (cosine
  ~0.992–0.999 on random fixtures).
- Byte-identity is structural (drafts only feed the existing verify) and
  was confirmed on every A/B run.

## Measured (M5 24 GB, greedy, same-session A/B vs MTP k=3)

| Case | MTP | DFlash2 | accept profile (MTP / DFlash2) |
| --- | ---: | ---: | --- |
| bench chat prompt, 128 tok | 11.38 | **11.81 (+3.7%)** | 75/34/18 vs 75/53/42/33/25/25 |
| raw code prompt, 96 tok | **15.58** | 13.76 (−11%) | 84/69/44 vs 74/65/57/43/39/35 |
| raw prose prompt, 96 tok | **13.46** | 10.70 | 78/59/27 vs 73/57/30/23/17/17 |

Tokens per round: 3.53 vs 2.27 on the bench prompt — the drafter is
genuinely better, consistent with llama.cpp's independent finding (+3%
over MTP-class on prose). Absolute numbers ran below the documented 15.1
because the host was under session load; the A/Bs are same-session.

## Why it doesn't win more (and what would change that)

The verify pass costs `fixed + k x per_row`, with per_row ≈ 15 ms from the
per-row sequential attention / GDN dispatches. k=6 pays that tax six times
per round vs MTP's three, which eats most of the acceptance advantage.

1. **Batch the verify rows** (multi-row attention + GDN in the verify pass
   instead of per-row dispatch). Benefits MTP too; this is the unlock that
   would let DFlash2's 3.5+ tokens/round convert into throughput.
2. **Acceptance gap at later positions** vs the reference's reported ~4.8
   average: worth a fixture comparison on *real* taps (not random) against
   the MLX reference to rule out a conditioning-quality delta.
3. The lm-head full-logits pass (0.65 GB/round) is most of the 32 ms draft
   cost; a chunked top-16 head (the `lm_head_greedy` chunking pattern)
   would roughly halve it.
