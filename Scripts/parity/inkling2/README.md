# Inkling 2 Mini reference tools

The base reference for the Inkling 2 Mini family is the shipped weights file
run through stock upstream llama.cpp, built locally. These are the tools that
build it, run it safely on a shared 32 GB Mac, and write the goldens in
[`Tests/Mference/Fixtures/Inkling2/`](../../../Tests/Mference/Fixtures/Inkling2/README.md).
Nothing here is part of any product target, and nothing downloads anything.

| File | What it does |
|---|---|
| `llama/Makefile`, `llama/embed_metal.sh` | Builds upstream llama.cpp (a clean checkout at a release tag) without cmake: ggml-base, the CPU backend (native, llamafile, CPU repack, Accelerate), the BLAS backend (Accelerate), the Metal backend with its kernels embedded as upstream's default build does, libllama, llama-common, mtmd and the server libraries. Tools: `llama-cli`, `llama-server`, `llama-bench`, `llama-completion`, `llama-eval-callback`, `llama-tokenize`, `llama-gguf`, `ink-golden`. Writes `BUILD_INFO.txt` (tag, commit, flags, binary SHA-256s). |
| `ink_golden.cpp` | `tokenize`, `chat` (vocabulary only) and `generate` (greedy continuation, top-K log-probabilities, the per-visit trace through the scheduler's eval callback). |
| `gguf_header_dump.py`, `tensors_tables.py` | Header and tensor table from the GGUF without loading weights (stdlib; type ids and block sizes from the checkout's `gguf-py/gguf/constants.py`). |
| `guarded_run.sh` | Wraps one model command: preflight, no other model process, AC power for timing runs, swap sampled every 2 s (any growth stops the run, exit 70), peak footprint. Refuses to run outside a `lock.sh run` hold, and refuses tools and settings that read the weights into memory instead of mapping them (`llama-gguf`, quantize/split/hash tools, any `-lm`/`--load-mode` other than `auto` or `mmap`, `LLAMA_ARG_LOAD_MODE`, older `--no-mmap`/`--mlock` spellings). After a trip: INT, TERM, then KILL, each bounded. |
| `vocab_goldens.sh` | Tokenizer and chat-template goldens. |
| `golden_stage.sh` | One weight-loading golden stage (Metal, Metal again, CPU-only: for `--ngl 0` ink-golden opens no GPU device and turns op offload and CPU weight repacking off, so the weights stay mapped). Stage `metal5` runs prompt set 5 (`inputs/generate_prompts_5.json`, trace02's prompt untraced) on Metal. |
| `baseline_stage.sh` | One baseline timing stage (llama-bench at 512, 4,096 and 16,384 tokens; llama-completion on real text for time to first token). Waits until at most one other swift build or test job runs. |
| `acceptance_stage.sh` | One C4 acceptance stage as one guarded hold: starts a release `MferenceServer --library` on 127.0.0.1 (`--max-context 40960 --prompt-cache-mode off`), waits for its ready line, checks `/v1/models` and the corpus manifest, runs `agent_acceptance.py` for the stage (`load-inkling`, `swap`, `slice1-*`, `gate-*`, `gate:<inkling\|deep>:<blocks>`), and stops the server on every exit (TERM reaches it; INT can be ignored under `&`). |
| `next_token_quality.py` | How well three teacher-forced runs (for example the runner, llama.cpp Metal, llama.cpp CPU) predict real text: the log-probability each gives the true next token at original-prompt positions of the natural-text prompts, per run and as paired differences with a seeded bootstrap; no run is the reference. |
| `g6c_verdict.py` | Tier G6c (spec v1.12, re-based on the exact model) for a runner's teacher-forced output (`inputs/generate_prompts_tf.json`) and its traces (`--traces`), with K4's reference runs (`--precision-root`, default `$INK/results/k4/precision`). Rule 2 is (a) the runner against `.fp32` on the ten teacher-forced prompts of at most 347 tokens and the three traces (listed bounds; expert sets differing on at most 2% of token-visits, each flip below margin 0.0258, from per-visit `margins` in trace.json), (b) `.llamaCPU` under 32 tokens or `.llamaExperts` from 32 up against `generate-tf/metal` (required on trace02, g06, lp09), (c1) the runner within 2x the addendum bounds of `generate-tf/cpu`, (c2) no farther from it than `.fp32` (+10%, addendum floors), (d) next-token quality against llama.cpp Metal and CPU; rules 3 (pooled) and 4 (traces) as in v1.8. Every reference position must be compared. Prints (a)'s bounds re-derived as max(3x the measured worst, the listed bound) and flags one that would loosen; the gate keeps the listed bounds. For the record only: rule 2 as written in v1.8 (the addendum bounds) and plain v2. Exit 0 pass, 1 fail, 4 incomplete (a rule's required inputs missing, or no traces). Self-test `test_g6c_verdict.py`. |
| `runner_dump_to_goldens.py` | Converts a native runner's raw dump (per prompt: ids, dumped positions, F32 logits rows; for traces the F32 per-visit hidden states and expert ids) into the layout `g6c_verdict.py` reads, with ink-golden's log-prob semantics (log-softmax over the first 200,058 logits after the softcap, top 20, ties to the lower id), and checks ids and positions against the reference. Self-test `test_runner_dump_to_goldens.py`. |
| `g5_server.py` | G5-server: the fixed chat requests of `g5_server_cases.md` against a running `MferenceServer` (`run`), and the comparison of two runs, a control server and a candidate (`compare`: status, content, reasoning, tool calls parsed and as sent, finish reason and usage; exit 0 same, 1 a difference, 2 a case missing). `g5_server_stage.sh` runs one server process (`--model <family>` or `--library`, `--max-context 4096`) as the command of one plain guarded hold. Self-test `test_g5_server.py`. |
| `native_stage.sh` | One native stage of the baseline table: release `MferenceCLI` on the Inkling 2 install with the baseline's three real-text prompts (SHA-256 checked), greedy, the same context and new-token counts as the llama.cpp `text-*` stages, `--verify trusted-receipt` (no hashing inside the timed prefill), no warm-up, through `guarded_run.sh --timing`; moves an earlier attempt aside; surfaces the CLI's `error:` line (for example an expert plan over the host budget). |
| `native_table.py` | The native table: `baseline.md`'s columns plus two ratio columns, against its `text-*` rows (prefill, decode, TTFT) and against stock llama.cpp on an all-Metal GGUF (`--metal-baseline`; "pending" until that run exists). |
| `run_held_stages.sh` | All the weight-loading stages in order, each as its own machine-lock hold. |
| `make_acceptance_corpus.py` | Builds the frozen agent-acceptance-v1 corpus (C4: Inkling 2 Mini vs Deep): blocks B (tool loops with the app's tools and fixtures), C (repository documents at 4K to 28K tokens), D (multi-turn), E (constrained writing), the gate and full tiers, a SHA-256 manifest; every repository file read at a given commit. |
| `agent_acceptance.py` | Loopback client for that corpus and block A (the release screen, scored by its own `score()`): plays the tool side from fixtures, deterministic scoring, failures in the denominator, create-only JSONL; `summarize` (Wilson intervals, failure taxonomy) and `paired` tables. Never starts a model. |
| `test_agent_acceptance.py` | Its self-test against a scripted fake SSE server; with `AGENT_ACCEPTANCE_CORPUS` set, every case's gold reply must pass and a non-answer must fail. |
| `make_tf_prompts.py` | Teacher-forced prompts from a set of goldens: each log-prob golden's prompt ids plus its generated ids as one `"kind": "ids"` prompt (no re-tokenization), recorded at the golden's positions; compare with `compare_goldens.py --teacher-forced`. |
| `noise_table.py` | The per-prompt and pooled noise tables (and per-trace rows) of the G6 proposal from `compare_goldens.py --json` outputs. |
| `compare_goldens.py` | Agreement between two `generate` outputs: token identity, top-1 agreement, log-probability deltas, approximate KL over the top 20, hidden-state error and routed-expert agreement per layer visit. |
| `ignore_merges_words.py` | The 337 vocabulary entries plain BPE merges split, from the GGUF header (tokens, merges) without touching tensor data. |
| `inputs/` | The frozen inputs: tokenizer texts, chat cases, generation prompt sets 1-4 (`generate_prompts*.json`; a prompt may set `logprobs_last` to record only its last N positions; set 4 is `trace01b`, trace01's prompt ids plus its greedy token as one `ids` prompt, traced CPU-only by stage `cpu4`). |

Build (one build job; the checkout must be clean and at the tag):

```bash
make -f Scripts/parity/inkling2/llama/Makefile LL=<llama.cpp checkout> OUT=<build dir> TAG=b12641 -j4 all ink-golden
```

`llama-gguf <file> r` is built but must not be pointed at a large GGUF: its
read mode allocates every tensor in heap memory. `guarded_run.sh` refuses it.
